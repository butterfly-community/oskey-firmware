# NXP A5000 seed 存储

`CONFIG_OSKEY_NXP_SE` 默认关闭。关闭时继续使用原有 Flash seed、软件 PIN 限次及签名流程，不编译 nano-package、PSA 适配和管理页面。开启后 seed 的持久存储与 PIN 认证使用 A5000R2HQ1；链派生、交易签名和 FIDO 仍在 MCU 上执行。

## 外部库与构建

`lib/nano-package` 是 Git submodule，固定在 `26d55b43225bc84de364057660cba676fa69f6e4`（1.6.1）。执行 `git submodule update --init --recursive` 获取依赖。项目通过 `cmake/nxp.cmake` 选取其 APDU、SCP03、T=1 over I2C 源文件，上游代码不作修改，不使用其 TinyCrypt 或旧 mbedTLS 后端。

所有构建在同一个 shell 中先执行：

```sh
source ~/Develop/platform/zephyr-project/.venv/bin/activate
source ~/Develop/platform/zephyr-project/zephyr/zephyr-env.sh
source ~/.esp.sh
command -v west
test -n "$ZEPHYR_BASE"
rustc +esp --version
```

开启功能需要三个配置：

1. `CONFIG_OSKEY_NXP_SE=y`。
2. Devicetree `chosen` 中的 `oskey,secure-element` 指向 `nxp,a5000` 节点。`boards/overlay/nxp_a5000.overlay` 使用 I2C0、地址 `0x48`；板级 overlay 负责引脚和总线速率。其他总线可自行提供节点与 chosen。可选 `enable-gpios` 按 GPIO flags 指定有效电平。
3. `CONFIG_OSKEY_NXP_CREDENTIALS_HEADER` 指向私有凭据头文件的绝对路径。未设置时构建仍能完成，页面显示连接凭据未配置，不能创建钱包，不回退到 Flash。

ESP32-S3 立创板构建示例：

```sh
west build -b esp32s3_devkitc/esp32s3/procpu -d build/nxp \
  -S espressif-flash-16M -S espressif-psram-8M -- \
  -DCONFIG_OSKEY_NXP_SE=y -DCONFIG_OSKEY_DISPLAY=y \
  -DCONFIG_OSKEY_STORAGE=y -DCONFIG_OSKEY_ESP_SPIRAM=y \
  -DEXTRA_CONF_FILE=boards/esp32s3_lichuang.conf \
  '-DDTC_OVERLAY_FILE=boards/esp32s3_lichuang.overlay;boards/overlay/nxp_a5000.overlay' \
  -DCONFIG_OSKEY_NXP_CREDENTIALS_HEADER=/absolute/private/a5000_credentials.h
```

私有头文件定义 `OSKEY_NXP_CREDENTIALS`，其值是 `struct nxp_credentials` 的初始化器，包含 `.enc`、`.mac`、`.dek`、`.reset` 四个 16 字节数组。前三者必须与芯片的 Platform SCP03 密钥匹配；`.reset` 必须匹配预置的 factory-reset UserID，或用于首次创建尚不存在的该对象。每台设备使用独立凭据，不提交到仓库。此方式把凭据放入固件，部署时需由 MCU 安全启动、Flash 加密及调试访问控制保护。项目不提供通用默认密钥，不修改已有的未知凭据，也不自动调整芯片的 transport lock 或全局 SCP 配置。

连接时认证读取 applet 版本，仅接受 7.2 系列。所有应用命令均走完整 Platform SCP03。生产配置应在芯片预置流程中强制 Platform SCP，并配置与固件匹配的密钥和 reset UserID。

## 对象和生命周期

| 对象 | ID | 内容 / 访问 |
| --- | --- | --- |
| PIN | `0x4f534b01` | 16 字节 UserID，10 次认证上限，无单独读写删除权限 |
| seed | `0x4f534b02` | 64 字节 BIP39 seed，仅 PIN 会话可读，要求安全消息，不允许覆盖或单独删除 |
| salt | `0x4f534b03` | 每钱包随机 16 字节，安全通道内可读，不允许覆盖或单独删除 |
| factory reset | `0x7fff0205` | 独立擦除认证凭据，无 seed 读取权限 |

PIN 先经过现有钱包的 PIN 派生，再以每钱包 salt 和 `OSKEY/A5000/PIN/V1` 域分隔进行 HMAC-SHA256，取前 16 字节作为芯片 UserID。派生结果不写入 MCU 的 seed 或失败计数槽位。

初始化先确认三个钱包对象均不存在，并验证擦除凭据可用，再写入 salt、PIN 和 seed。最后使用 PIN 认证并回读核对 seed。任一步失败都不报告初始化成功；部分对象已存在时拒绝重新创建，必须清除钱包恢复。

开启安全芯片配置时，如果 Flash 中仍有旧软件 seed，拒绝初始化和解锁，并在管理页提示先备份、清除。不会自动导入、覆盖或删除旧软件钱包，也不会让两种 seed 后端同时生效。应在原软件固件中确认恢复词备份并清除钱包，再切换配置、重新导入；已有芯片钱包时，更换为软件配置也应先备份并清除芯片钱包。单纯更换固件不能把已有 seed 的保护方式自动升级。

每次提交 PIN 只发起一次认证，通信超时不自动重试。芯片保存失败次数，正确 PIN 可重置未耗尽的计数；耗尽后正确 PIN 也不能恢复旧 seed。应用不会在达到上限时自动擦除，也不提供重置 PIN 对象或绕过限次的入口。

认证成功后，seed 暂存于 Rust `Zeroizing` 内存。锁定、失败的重新认证、刷新连接及清除操作会丢弃缓存；PIN 派生值、临时 seed、PSA key 和会话数据均有清理路径。芯片异常不会切换到软件 seed。上游敏感日志始终关闭，不受应用日志开关影响。

清除钱包在独立 factory-reset 会话中执行 `DeleteAll`，随后重新建立安全通道并验证三个钱包对象均已删除，才清除设备 Flash 并重启。它会删除芯片上所有非 NXP 预置对象，因此该芯片由钱包独占。删除过程的响应丢失不等同于失败或成功，重新读取的对象状态决定结果。

## 页面

初始能力页、设置页、PIN 解锁页及存储错误页均可进入 **NXP secure element**。页面提供状态、初始化入口、PIN 解锁、锁定、刷新连接和带确认的清除钱包。初始化入口先设置并确认 PIN，再进入创建或导入流程。刷新也会锁定当前钱包。页面从原子状态快照读取信息，不在 LVGL 回调中执行 I2C。

A5000 的 UserID 不报告有效的剩余重试次数，因此页面显示 10 次规则，不显示估算倒计时。认证被拒绝时显示“PIN rejected or attempt limit reached”。锁定恢复只能清除钱包并重新初始化。

## 验证

```sh
cmake -S tests/nxp -B build-nxp-unit
cmake --build build-nxp-unit -j4
ctest --test-dir build-nxp-unit --output-on-failure

cmake -S tests/nxp -B build-nxp-sanitize -DNXP_SANITIZE=ON
cmake --build build-nxp-sanitize -j4
ctest --test-dir build-nxp-sanitize --output-on-failure

cargo test --manifest-path lib/core/Cargo.toml -p oskey-action \
  --no-default-features --features crypto-psa,crypto-link -- --test-threads=1
cargo test --manifest-path tests/nxp/Cargo.toml -- --test-threads=1
cargo test --manifest-path tests/integration/Cargo.toml
```

五组 C 测试覆盖 PSA 标准向量与资源释放、PSA 调用失败、芯片对象状态与持久限次、初始化及清除故障、APDU 策略和严格长度检查，以及真实 nano-package SCP03 加解密向量与篡改拒绝。芯片持久状态使用独立模型；协议边界使用可注入的传输替身。Rust 测试覆盖硬件后端不读写软件 seed、锁定跨运行时重建、连接恢复、失败清理、管理操作完成事件，以及两种后端生成一致签名。固件适配层测试直接编译生产 Rust 代码，验证旧软件 seed 和存储错误阻止切换后端、显式清除后的可用状态及关闭功能时的原有路径。测试模型不能证明芯片预置参数与板级接线正确。

实现仅保留一个串行安全通道和一个增量 CMAC 上下文，使用固定 64 字节 seed 缓存；不另建软件重试计数、PIN 重置或后台认证重试路径。PSA 适配仅覆盖上游实际调用的密码接口，避免把 nano-package 的其他存储和密码功能引入钱包。

`tests/nxp/native_regression.py` 用临时 PTY 连接 native_sim 和已有 `tests/integration` UART 程序，使用临时 RAM Flash。先构建集成程序，再传入 firmware 路径：

```sh
cargo build --manifest-path tests/integration/Cargo.toml
python3 tests/nxp/native_regression.py build/nxp-disabled/zephyr/zephyr.exe --wallet
python3 tests/nxp/native_regression.py build/nxp-enabled/zephyr/zephyr.exe
```

软件后端的完整 UART 钱包回归需关闭显示并启用 `CONFIG_OSKEY_TEST_FIRMWARE` 自动确认。该选项仅用于测试构建。NXP 配置未提供连接凭据时可验证协议与失败关闭状态，完整安全存储状态转换由上述单元测试覆盖。
